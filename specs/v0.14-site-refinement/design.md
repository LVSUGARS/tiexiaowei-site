# v0.14 站点整理与体验完善设计

## 1. 设计原则

1. 一级导航只回答一个明确问题；同一层级全部是直达入口。
2. 首页负责首次认识和当前重点，侧栏负责栏目内继续浏览，正文负责单篇内容。
3. 数据驱动的页面只保留一个数据源；人工策展和自动索引分开。
4. 隐藏入口不等于权限控制，公开站点必须诚实表达安全边界。
5. 先修正文案与入口一致性，再做视觉微调；不为“看起来丰富”增加新的交互层。

## 2. 目标信息架构

```text
首页 /
├─ 关于 /about/
│  ├─ 中心简介 /about/
│  ├─ 全国荣誉 /about/awards
│  ├─ 新媒体矩阵 /about/matrix
│  └─ 合作与链接
│     └─ 友情链接 /friends/（不进入主导航）
├─ 部门 /department/
│  ├─ 部门职能（常青页）
│  └─ 按年年册（2026、2025…）
├─ 活动 /activity/
│  ├─ 精选活动
│  ├─ 时间轴与历史上的今天
│  └─ 年度总结
├─ 档案馆 /archive/
│  ├─ 资料库 /resources/
│  ├─ 文章库 /library/
│  ├─ 主题标签 /tags/
│  └─ 口述史 /stories/
└─ 加入我们 /guide/
   └─ 成员端（外部系统，导航保留为单独行动入口）
```

公开顶栏固定为：`首页 / 关于 / 部门 / 活动 / 档案馆 / 加入我们 / 成员端 ↗`。搜索、外观切换等工具保留在右侧；维护者从页脚和纠错行进入，不占用访客一级选择。

## 3. 页面入口矩阵

| 页面/入口 | 首要任务 | 允许出现的下一步 | 不应承担 |
| --- | --- | --- | --- |
| 首页 | 认识中心、看到当前重点 | 关于、活动、档案馆、加入、成员端/报名 | 完整站点目录、友链列表 |
| 关于 | 解释“我们是谁、如何关注、与谁合作” | 简介、荣誉、矩阵、友情链接 | 活动台账、资料检索 |
| 部门 | 解释“谁在做什么” | 职能页、年册、加入我们 | 单场活动详情 |
| 活动 | 浏览发生过的工作 | 年份、活动详情、年度总结 | 资料条目全文 |
| 档案馆 | 解释沉淀物分类 | 资料、文章、标签、口述史 | 把四个库再复制进顶栏 |
| 资料库/文章库 | 列表和检索 | 单条内容、收录指南/规范 | 改写全站导航 |
| 加入我们 | 完成报名或了解岗位 | 部门、报名、成员端 | 展示内部管理入口 |
| 维护者 | 交接和贡献说明 | 更新教程、维护指南 | 成为公开主导航栏目 |

## 3.1 入口去重规则

同一个目的地允许有多个“语境入口”，但不得在同一视觉层重复：

- `/about/` 可同时由顶栏和首页 Hero 的“了解我们”进入；关于侧栏内部不再重复一个“关于我们”别名。
- `/activity/` 可由顶栏和首页精选卡进入；活动页不再复制档案馆四库卡片。
- `/archive/` 由顶栏直达，四个子库只在档案馆总览和各自局部侧栏出现。
- `/friends/` 只在关于侧栏出现；正文中的合作说明可以提到“合作链接”，但不再放第二个大按钮或首页卡片。
- `/maintainer/` 只由页脚、纠错行和维护文档互链进入，不放入访客一级导航。

## 4. 侧栏与 URL 规则

- `/about/` 与 `/friends/` 共享关于侧栏；“合作与链接”默认折叠。
- `/department/` 只显示职能和按年年册；当前年展开，旧年折叠。
- `/activity/` 只显示总览、年度总结和年份锚点；单篇活动不登记。
- `/archive/` 只显示四个库入口；资料、文章、标签、口述史页面分别使用局部侧栏。
- `/resources/` 和 `/library/` 的条目继续由列表组件生成，不把单篇条目塞入配置文件。
- 保留 `/friends/`、`/maintainer/`、`/demo/` 等既有 URL；调整入口不等于删除页面。

### 4.1 侧栏判定表

| 当前 URL 前缀 | 使用的侧栏 | 允许的分组 | 禁止出现 |
| --- | --- | --- | --- |
| `/about/`、`/friends/` | `aboutSidebar` | 中心概况、关注我们、合作与链接 | 活动年份、资料单篇 |
| `/department/` | 部门侧栏 | 部门职能、按年年册 | 单场活动、资料条目 |
| `/activity/` | 活动侧栏 | 活动总览、年度总结、年份锚点 | 资料/文章库分组 |
| `/archive/` | 档案馆侧栏 | 档案馆介绍、四类库入口 | 单篇档案 |
| `/resources/` | 资料库侧栏 | 总览、收录指南 | 具体资料条目 |
| `/library/` | 文章库侧栏 | 文章目录、规范、校园号 | 每篇文章标题 |
| `/tags/`、`/stories/` | 各自局部侧栏 | 本栏目总览 | 其他栏目完整树 |

## 5. 首页结构

首页从上到下保持四段：

1. Hero：中心名称、学校归属、四端矩阵定位和“了解我们/加入我们/文章库”行动。
2. 节气徽章：作为轻量彩蛋，链接到荣誉专题；默认 SSR 文本可用，客户端再设置色相。
3. 精选内容：活动工作台账、资料库、文章库三张卡；数据不足时显示建设状态而不是伪造动态。
4. 系统入口：成员端和新生报名，两者从 `appLinks.ts` 统一读取。

不再新增“站点导航”整套卡片，也不在首页放友情链接或维护者入口。

### 5.1 首屏内容优先级

在 1280px 桌面宽度和常见手机宽度下，首屏必须按以下顺序可识别：

1. 品牌名称与学校归属。
2. “了解我们 / 加入我们 / 文章库”三个 Hero 行动。
3. 节气徽章（装饰性，不阻塞主要行动）。
4. 向下滚动后先看到精选内容，再看到系统入口。

任何新增横幅、照片墙或统计卡都不得把主要行动推到首屏不可见；招新横幅继续受 `siteBanner.js` 开关控制。

## 6. 数据与自动化边界

| 能力 | 唯一来源 | 构建结果 | 维护动作 |
| --- | --- | --- | --- |
| 活动时间轴/历史上的今天 | `docs/activity/*.md` frontmatter | 活动列表、时间轴、日期匹配 | 新增活动 md |
| 资料库列表 | `docs/resources/*.md` frontmatter | `ResourcesList` 卡片 | 新增资料 md |
| 标签索引 | 活动与资料的 `tags` | `TagsIndex` 分组 | 在 frontmatter 加标签 |
| 文章库 | `data/article-catalog.template.csv` | `ArticleList` 按年目录 | 追加 CSV 行 |
| 首页精选 | `data/homeNav.js` | 三张精选卡 | 仅改数据文件 |
| 外部系统入口 | `appLinks.ts` | 顶栏、首页、招新 CTA | 仅改链接配置 |
| 节气 | `data/solarTerms.js` + 运行时日期 | 徽章与首页色相 | 更新近似日期表/说明 |
| 固定公历节日 | `data/festivals.js` + 运行时日期 | 节日徽章 | 增加固定日期；农历节日待可靠年历 |
| 节日/节气文章关联 | `article-catalog.template.csv` | 命中月日时链接最近年份文章 | 先补目录，标题包含事件名可提高匹配准确度 |

活动页、档案馆页和维护教程中的“待 M3”文字必须与上表同步。文章库仍是目录索引，不在本轮导入公众号原始 HTML。

## 7. 友情链接边界

页面继续保留在 `/friends/`，但只从关于侧栏进入，并在标题或说明中明确“公开链接收纳”。这解决信息架构问题，不提供安全隔离。若后续需要成员可见，方案应是将真实链接移入成员端或受保护网盘，公开站只保留申请说明。

## 8. 节气计算设计

- 以 `Asia/Shanghai` 的月日作为匹配键，避免访客设备时区导致跨日误判。
- 节气徽章只在月日与 `solarTerms.md` 完全相等时出现；其他日期返回空值，不显示“今日”文字。
- 继续允许近似 ±1 天，但在数据文件和维护教程中显式标注；若追求天文精度，另开数据升级任务，不在本轮引入运行时网络依赖。
- SSR 不输出依赖构建日期的节气徽章；客户端挂载后再按当天计算并设置 `--seasonal-hue`，非节气日移除变量回退品牌蓝。

实现时应把“北京时间月日”和“当天事件匹配”封装成可单测的纯函数或等价的可替换边界，不能在多个组件分别实现日期判断。测试至少覆盖：`01-01 -> 元旦`、`01-05 -> 小寒`、`05-04 -> 五四青年节`、`09-07 -> 白露`、`09-08 -> 无徽章`。当前节气表仍是近似数据，不承诺天文时刻级准确;农历节日需另接可靠年历。

文章关联采用保守策略:先筛选与当天月日相同的已收录文章,再优先选择标题包含事件名的记录,最后回退到该日期最近年份记录。没有完整公开链接的目录行不参与链接,但不会阻止节日名称显示。

## 9. 验证方案

### 静态层

- `pnpm build`
- `pnpm audit`，记录实际漏洞和锁定版本，不把失败改写成通过
- `git diff --check`
- 递归扫描 `docs/.vitepress/dist/**/*.html`，检查顶栏链接、友情链接收纳和组件 DOM 标记。

### 浏览器层

- 桌面：`/`、`/about/`、`/activity/`、`/archive/`、`/resources/`、`/friends/` 六条路由，确认一次点击路径和无控制台错误。
- 移动端：至少一个窄屏视口，打开菜单并点击每个一级入口；确认不换行、不溢出、侧栏层级可理解。
- 节气：使用当前日期与跨年边界各检查一次；确认徽章文字和色相变量存在。
- 线上缓存：发布后用带查询参数的新 URL 或硬刷新复核，不能只凭旧浏览器标签判断版本。

### 9.1 产物扫描断言

递归扫描所有 `dist/**/*.html`，至少输出以下断言结果：

- 首页存在 `VPHero` 产物文本和系统入口链接。
- 任意顶栏 HTML 中存在七个目标链接，且不存在 `/friends/`。
- 关于侧栏或关于页面存在 `/friends/`，首页和档案馆页面不存在该入口。
- 活动页存在 `photo-wall`、`card-cover`；标签页存在 `tag-group`；资料页存在资料卡标题。
- 不依赖 `dist/assets/` 单层扫描，因为 Vite 可能把组件 chunk 放入更深目录。

### 9.2 失败处理

- 构建失败：停止交付，先修 Markdown/Vue 模板错误。
- audit 失败：保留命令原始输出，标记依赖风险；未经批准不得升级版本。
- 浏览器无法启动：报告“浏览器层未验证”，不能用构建通过替代。
- 线上与本地产物不一致：优先检查缓存和部署同步，不回滚内容文件。

## 10. 实施边界

主要变更文件预计集中在 `docs/.vitepress/config.mts`、`docs/index.md`、`docs/archive/index.md`、`docs/activity/index.md`、`docs/maintainer/update-tutorial.md`、`docs/demo/nav.md`、`PLAN.md` 和必要的数据/组件说明；不应触碰部署配置或依赖版本。

### 10.1 变更分层

| 层 | 可改内容 | 审查重点 |
| --- | --- | --- |
| 配置层 | nav、sidebar、过时注释 | URL 不变、层级不混杂 |
| 内容层 | 说明、状态、教程、计划 | 不改事实、不虚构数据 |
| 数据层 | 节气说明、现有标签/条目元数据 | 不改变既有条目语义 |
| 组件层 | 仅在节气边界或验证暴露 bug 时改 | SSR/水合、无布局跳动 |
| 工程层 | 审计脚本或检查脚本的最小增强 | 不引入依赖、不改变部署 |
