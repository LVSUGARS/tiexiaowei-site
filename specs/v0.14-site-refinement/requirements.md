# v0.14 站点整理与体验完善需求

## 1. 背景与目标

v0.13 已完成一次导航重组，但站点仍存在“入口层级不统一、旧计划文案残留、自动化能力与说明不一致、首页重点不够明确”等问题。本轮目标是整理现有内容和入口，让第一次访问者能快速回答“这里是什么、做过什么、留下什么、如何加入”，让维护者能按一套规则继续扩展。

本轮只做站点信息架构、页面入口、文案和验证流程的完善，不改变部署方式、不升级依赖、不删除历史页面。

## 2. 用户与任务

### 访客

- 从首页认识铁小微，并在一次点击内进入关于、部门、活动、档案馆或加入我们。
- 在活动、资料、文章和标签之间浏览，不需要理解组件或文件结构。
- 从“关于”中找到新媒体矩阵和合作链接；友情链接不是公开主导航入口。
- 在手机上使用导航，不因多层下拉或重复入口迷路。

### 成员与内容维护者

- 新增活动、资料或标签时，只维护约定的数据文件或 Markdown frontmatter，列表和索引自动更新。
- 能从维护文档判断哪些能力已经上线，哪些仍需内部资料或授权数据。
- 能用固定命令完成构建、死链、产物 DOM 和移动端冒烟检查。

## 2.2 不变项清单（防返工）

以下内容在没有单独批准前不得改变：

- 所有既有 URL，包括 `/friends/`、`/maintainer/`、`/demo/` 和每篇活动/资料页面。
- 首页的 VitePress `layout: home`、Hero、节气徽章、精选内容和系统入口。
- `appLinks.ts` 作为成员端/报名链接的唯一配置点。
- `VPBadge` 不放进表格单元格或标题；团队页使用 `#members` 插槽。
- 依赖精确版本、GitHub Pages/域名配置、历史年册和活动档案。
- 现有真实内容和“待补”占位，不为了视觉完整而编造数据。

## 2.3 关键用户路径

### 首次访客

`/` → `关于` → `中心简介`；`/` → `活动` → 任意活动；`/` → `档案馆` → `资料库/文章库/主题标签/口述史`；`/` → `加入我们` → 报名系统。

每条路径的第一个箭头必须是一次点击，第二步只进入当前栏目内容，不需要先打开隐藏菜单。

### 维护者

`页脚站点维护` → `维护团队` → `数据更新教程` → 对应数据文件 → `pnpm audit` → `pnpm build`。

教程必须能解释“改哪个文件、是否需要改侧栏、如何验证产物”，不能要求维护者阅读组件源码才能完成常见更新。

## 3. 范围

### 3.1 本轮范围

1. 复核并固化一级导航、栏目侧栏和首页入口的职责边界。
2. 统一“关于”命名，友情链接只作为关于栏目下的合作链接保留。
3. 清理 v0.8/v0.10/v0.13 之间已经失效的计划状态、自动化说明和示例导航文案。
4. 明确节气徽章的日期来源、跨年兜底、时区和“近似日期”的产品提示。
5. 明确资料库、文章库、标签、活动时间轴之间的数据来源与维护责任。
6. 补齐桌面与窄屏浏览器验收方案，并将静态构建检查写成可重复步骤。

### 3.2 不在本轮范围

- 不删除或改写历史活动、年册和既有 URL。
- 不改 GitHub Pages、Cloudflare、域名、Docker 或部署流程。
- 不升级 VitePress、Vite、插件或锁文件版本；依赖漏洞单独评估。
- 不虚构负责人、照片、文章正文、报名信息或平台链接。
- 不把“隐藏导航入口”描述成真正的权限控制；静态站不能提供成员鉴权。
- 不实现留言墙、社交平台自动抓取或公众号原始 HTML 导入。

## 4. 验收标准（EARS）

### R1 一级导航清晰

- 当访客打开任意公开页面时，系统应提供一致的一级入口：`首页 / 关于 / 部门 / 活动 / 档案馆 / 加入我们 / 成员端`。
- 当访客点击一级入口时，系统应在一次点击内到达对应栏目总览，不使用同一层级的混合下拉菜单。
- 当视口宽度进入移动端断点时，系统应保持入口可读、可点击，且不得出现导航文字换行或横向溢出。

### R2 栏目边界和侧栏一致

- 当访客位于关于、部门、活动、档案馆、资料库、文章库、标签或口述史页面时，系统应只显示当前栏目相关的侧栏分组。
- 当访客浏览单篇活动、资料或文章时，系统不得把单篇条目加入侧栏；条目应从列表页或正文链接进入。
- 当访客从档案馆总览进入子库时，系统应在两次点击内到达资料库、文章库、主题标签或口述史。

### R3 友情链接收纳与边界

- 当访客浏览主导航、首页或档案馆导航时，系统不得展示“友情链接”入口。
- 当访客进入“关于”栏目时，系统应在“合作与链接”分组中提供友情链接入口。
- 当维护者需要真正限制链接访问时，系统应明确提示当前站点仅做导航收纳，不能替代鉴权或受保护存储。

### R4 首页保留且承担首访任务

- 当访客打开根路径 `/` 时，系统应渲染 Hero、当前重点/精选内容和成员端或报名等行动入口。
- 首页不得复制完整的顶栏目录；精选卡片应优先指向活动、资料、文章等当前重点内容。
- 首页内容为空或数据不足时，系统应显示诚实的建设状态，不得生成虚假的“最新动态”。

### R5 自动化说明与实际能力一致

- 当维护者新增符合 frontmatter 约定的活动或资料条目时，系统应在构建时自动更新对应列表、时间轴或标签索引。
- 当页面说明自动化仍处于“待 M3”但对应组件已经上线时，系统应改为当前真实状态或移除过时承诺。
- 当构建产物包含组件渲染内容时，递归扫描 `docs/.vitepress/dist` 应能找到目标 DOM 标记：`tag-group`、资料列表输出、`photo-wall` 和卡片封面样式。

### R6 节气显示可解释、可验证

- 当用户访问首页时，系统应按北京时间的当前日期判断是否命中节气日；只有命中当天才显示“今日”徽章，其他日期不渲染该徽章。
- 当节气表采用近似日期而非天文精确时，系统应在维护文档或组件注释中明确“约 ±1 天”的限制和更新方式。
- 当页面从服务端 HTML 水合到客户端时，节气徽章只在当天命中时出现；非节气日保持默认品牌色且不得残留上一节气文字。

### R7 文档与计划可维护

- 当维护者阅读 `PLAN.md`、更新教程或演示导航页时，系统文档应与当前 v0.13/v0.14 实际导航和自动化状态一致。
- 当依赖审计报告漏洞且版本被精确锁定时，规划和交付说明应记录风险与决策，不得以“审计全绿”掩盖失败。

### R8 不变项和回退可追溯

- 当本轮整理完成时，所有既有内容 URL 应仍能解析到页面，且 Git 历史中存在 v0.13 回退点。
- 当用户认为新结构不合适时，维护者应能仅通过 Git 回退恢复 v0.13 导航，不需要手工拼接页面。

## 4.1 可执行验收用例

| 用例 | 操作 | 通过条件 |
| --- | --- | --- |
| U1 顶栏 | 在桌面打开 `/`，依次点击七项入口 | 每项一次点击到达正确总览，无下拉层级 |
| U2 友链收纳 | 检查首页、顶栏、档案馆正文与侧栏 | 只有关于侧栏的“合作与链接”出现友情链接 |
| U3 首页保留 | 直接访问 `/` 并查看首屏和下方内容 | Hero、节气、精选内容、系统入口均存在 |
| U4 栏目隔离 | 打开活动、资料、文章、标签、口述史页面 | 侧栏只显示当前栏目内容，不出现其他库的单篇条目 |
| U5 自动列表 | 在临时分支新增带 frontmatter 的资料/活动 md 后构建 | 资料卡、时间轴、标签分组出现；撤销临时文件后产物恢复 |
| U6 节气 | 检查北京时间当天、`01-01`、`12-31` 三个边界 | 节气名称、emoji、色相都有值，跨年不为空 |
| U7 移动端 | 窄屏打开菜单并点击每项一级入口 | 菜单可关闭、文字不换行、页面不横向溢出 |
| U8 维护文档 | 新维护者只读教程完成一次资料条目更新 | 能定位文件并通过 audit/build，不需要猜测 |

## 5. 业务规则与决策点

- “关于”是公开身份与对外关系入口；友情链接属于其下的合作链接，不是独立一级栏目。
- “活动”记录发生过的工作，“档案馆”收纳可长期复用和检索的沉淀；二者不互相复制整页内容。
- “成员端”是外部系统跳转，不与本站内容栏目混排；地址只从 `appLinks.ts` 读取。
- 友链“不能外露”默认解释为不出现在主导航、首页和档案馆入口；若要求登录后才能访问，必须新增鉴权或受保护存储方案并另立需求。
- 节气“自动”指按日期运行时计算，不指向线上后台实时天文服务；精确节气数据需要单独引入可靠年历数据源。

## 6. 待确认事项

1. 是否接受当前七项一级导航作为 v0.14 的最终公开结构。
2. 友情链接是否只需“收纳不外露”，还是需要真正的访问权限控制。
3. 是否允许在不升级依赖的前提下，仅补充审计说明；若要求消除 Vite/esbuild 漏洞，需要单独批准版本升级评估。
